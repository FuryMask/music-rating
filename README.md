# Music Rating — Liquid Glass

[Сборка EXE, перенос в Git и выпуск обновлений](RELEASE.md)

Тёмный интерфейс в духе Apple Liquid Glass, отрисованный средствами Qt.
Стеклянные панели с бликами отделяют навигацию и поиск от матового холста
медиатеки. Боковая панель открывает главную, последние оценки, альбомы
и исполнителей. Добавление альбома находится в разделе «Действия».
`Ctrl+F` переводит фокус в поиск.

База хранится в `Документы\Music Rating\library.db`. На чистой установке
открывается регистрация, медиатека изначально пуста.
В «Профиль → Настройки» можно выбрать тему: Standart, Dark, Ruby, Emerald
или Topaz. Тема меняется сразу и сохраняется на этом компьютере.
Под темой находится настройка «Визуализатор» с режимами «Выключено»
и «Волна». Выбор сохраняется, при первом запуске выбрана «Волна».

## Оценивание с прослушиванием

На втором шаге локального оценивания нажмите кнопку с нотой вверху справа
и выберите Яндекс Музыку или Spotify. Для режима нужен настольный клиент,
Windows и Python 3.11+ с зависимостями из `requirements.txt`.
Music Rating сначала пытается запустить трек в уже открытом клиенте. Если
нужно открыть альбом, плеер запрашивает фоновый запуск. Дальше Music Rating
использует очередь клиента и медиасессию Windows. Вход в аккаунт
выполняется в клиенте, ключи Spotify API для прослушивания не нужны.
Настольная Яндекс Музыка ищется в `%LOCALAPPDATA%\Programs\YandexMusic`.

Если альбом сохранён с другим источником или создан вручную, вставьте ссылку
на его издание в выбранном сервисе. Для автозапуска первого трека в Spotify
и Яндекс Музыке плеер ищет кнопку нужной песни через Windows UI Automation.
При запуске Яндекс Музыки из Music Rating включается доступность Chromium.
Если Яндекс Музыка была открыта раньше и её кнопки недоступны, можно
запустить показанный трек вручную или закрыть клиент перед новой попыткой.

Поля оценок плавно заменяют обложку за 7 секунд до конца, а за 3 секунды
плеер ставит трек на паузу. Стрелка дослушивает финал, затем появляются
обложка и название следующего трека.
Через 5 секунд без движения мыши остаются обложка, название, исполнители и
полоса прогресса и волна. Курсор также скрывается в области плеера.
Движение мыши и появление полей оценок возвращают интерфейс. Переходы
длятся 0,3 секунды. Новый статус виден 5 секунд.
Затем его можно раскрыть, наведя указатель на стрелку.
Кнопка слева внизу переключает полноэкранный режим. Первый Esc в
полноэкранном режиме возвращает обычное окно и оставляет плеер открытым.
При выходе из прослушивания также восстанавливается обычное окно.
Крестик возвращает к таблице, не сбрасывая введённые оценки. База обновляется
только после нажатия «Готово» на итоговом шаге.

Фоновая волна использует акцент темы и реагирует на аудио выбранного
настольного клиента. WASAPI получает звук от его процесса и дочерних
процессов. Для волны нужна Windows со сборкой 20348 или новее.
В режиме уменьшенного движения волна отключена.

## Запуск

```bat
py -3.11 -m pip install -r requirements.txt
py -3.11 main.py
```

Разработано и проверено на Python 3.11 + PySide6 6.11.1 (Windows).

## Что появилось для пользователя

**Движение**

- **Смена страниц** — мгновенная (10–15 мс на переключение). Затухание
  со снимком прежней страницы отключено по умолчанию: снимок главной
  стоил ~26 мс и давал рывок ровно по клику, а сама анимация прятала
  новую страницу на 0.36 с. Если хочется — `MUSICRATING_PAGE_FADE=1`.
- **Карточки** — при наведении обложка приближается на 5 %, по краю
  появляется белая обводка, название белеет, «пилюля» оценки становится
  ярче; клик «пружинит».
- **Кнопки** — растут от центра при наведении, сжимаются при нажатии и
  дают волну от точки клика. Меняется только отрисовка: область нажатия
  и расположение соседних элементов остаются на месте.
- **Прокрутка** — мышь плавно прокручивает страницы и ленты за 120–180 мс,
  тачпад работает 1:1 без дополнительной инерции. Отключить сглаживание
  можно через `MUSICRATING_SMOOTH_SCROLL=0`.
- **Умное колесо над лентой карточек** — вертикальное колесо прокручивает
  страницу (лента больше не «ловит» его), Shift+колесо и горизонтальный
  жест листают саму ленту.
- **Каскад появления** — карточки главной при возврате и строки
  треклиста на странице альбома всплывают по очереди.
- **Панель поиска** проявляется при открытии.

**Стиль**

- Холодная сине-фиолетовая палитра и голубой акцент; у навигации,
  полей, кнопок и диалогов общие визуальные состояния.
- Крупная типографика заголовков, «пилюли» оценок, скруглённые карточки
  и поля, тонкие скроллбары, оформленные подсказки и меню.
- Обложки: диагональный градиент у заглушек и тонкая светлая линия по
  внутреннему краю — даже пустые обложки выглядят объёмными.
- Плитка «Смотреть все»: шеврон под подписью подсвечивается акцентом и
  сдвигается при наведении.

**Доступность**

- `MUSICRATING_REDUCED_MOTION=1` выключает всю моторику (переходы,
  прокрутку, каскады, волны) — интерфейс сразу в конечном состоянии.

**Правки Task 40–45 (по фидбеку)**

- **Прогруз страниц (Task 45).** Возврат на главную больше не пересобирает
  все карточки: у страницы есть отпечаток данных, и при неизменной базе
  `refresh()` выходит сразу (замер: 170 мс → 0 мс). Добавлен кэш
  декодированных обложек/фото (карточка: 1,8–3,2 мс → ~1,1 мс), фильтр
  событий приложения получил дешёвый ранний выход, а снимок перехода
  переведён на непрозрачную отрисовку. Итог: полный цикл «альбом →
  назад» — 281 мс → **~14 мс**. Затухание страниц оставлено опцией
  `MUSICRATING_PAGE_FADE=1` (снимок главной всё равно стоит ~26 мс).
- Анимации замедлены суммарно примерно в 1,8 раза от исходных Task 39:
  ховер 450 мс (было 250), смена страницы 360 мс, нажатие/возврат
  120/220 мс, волна 700 мс, подъём карточек диалогов 320 мс, каскады —
  340 и 300 мс с шагом 22–24 мс, тосты 220/280 мс. Task 43 — финальная
  подстройка: основные анимации сокращены ровно на ~100 мс от самого
  медленного варианта, чтобы темп не был «тягучим». Прокрутка намеренно
  быстрее остальных анимаций (0.14–0.22 с): длинная инерция ощущалась
  как «залипшее» колесо.
- Скролл: найдена настоящая причина лагов. QScrollArea прокручивается
  ПЕРЕМЕЩЕНИЕМ виджета-контента и перерисовывает вьюпорт целиком; замер
  показал 9 полных перерисовок 1057×744 за один щелчок колеса (~14 мс
  каждая) — инерция из 8–10 кадров давала рывки. Теперь колесо работает
  нативно (одна перерисовка на щелчок, Qt сам объединяет серию), шаг
  120 px, тачпад — 1:1 по pixelDelta, лента карточек листается сразу.
  В текущей версии сглаживание снова включено по умолчанию; для слабых
  машин его можно отключить через `MUSICRATING_SMOOTH_SCROLL=0`.
  Обложки дополнительно кэшируются в отмасштабированном виде (раньше
  каждая перерисовка smooth-масштабировала фото 500→160 px).
- Исправлен баг «карточка осталась увеличенной и растёт дальше»:
  база размера фиксируется только при входе из покоя (повторный Enter
  не принимает увеличенный размер за новый), а пока курсор над
  элементом, сторож раз в 110 мс сверяет позицию курсора — если курсор
  ушёл без Leave (быстрая проводка, прокрутка), элемент плавно
  возвращается к своему размеру.
- Исправлен раздув карточки при возврате на главную: Qt присылает
  Enter ещё ДО раскладки, когда свежая карточка имеет размер по
  умолчанию 640×480. Теперь ховер откладывается до раскладки (до
  ~200 мс, с повторами), база никогда не берётся из «дефолтного»
  размера, а если раскладка так и не пришла — размер ограничивается
  sizeHint. Иконки с фиксированным размером (40×40) больше не
  дёргаются: масштаб для них не анимируется, остаются обводка, волна
  и нажатие.

## Заметки для будущих правок

- Для новых элементов интерфейса используйте короткое затухание, а для
  появляющихся блоков сочетайте его с небольшим сдвигом. Оставляйте
  место под анимацию, чтобы соседние элементы не прыгали.
- Глобальное правило `* { background-color: ... }` красит **каждый**
  bare QWidget. Поэтому градиент НЕЛЬЗЯ класть на фон страницы: под
  текстами и контейнерами проступят прямоугольники. Глубина делается
  слоями панелей (полоса/сайдбар/холст) — см. комментарий в `theme.py`.
- QGraphicsOpacityEffect нельзя вкладывать: не навешивайте его на
  страницу/оверлей, внутри которых уже есть эффекты (карточки,
  карточка диалога). Для смены страницы используется снимок с ручной
  отрисовкой (`page_stack.py`).
- Любая новая «кнопка» — наследник `Hoverable`/`HoverButton`: ховер,
  пружина и волна заработают сами.
